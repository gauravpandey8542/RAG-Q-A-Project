# AI Examiner: RAG Question Answering over PDFs

A FastAPI backend that lets you upload a PDF and ask questions about it. Answers are generated by an LLM using only retrieved passages from the document, and each answer comes with the source pages it used. If the document doesn't contain the answer, the system says so instead of guessing.

## How it works

1. **Upload:** a PDF is saved and its text is extracted page by page.
2. **Chunk:** each page is split into overlapping chunks (about 1000 characters, 150 overlap).
3. **Embed and store:** chunks are embedded with Chroma's default embedding model and stored in a local ChromaDB database with page numbers.
4. **Retrieve:** a question is embedded and the 4 most similar chunks are fetched.
5. **Generate:** the chunks are put into a prompt and sent to `gpt-oss-120b` (via Groq's API), which answers using only that context and cites passages as [1], [2].
6. **Respond:** the API returns the answer plus the source chunks and page numbers so claims can be checked.

Uploads are deduplicated using a hash of the file contents, so uploading the same PDF twice doesn't create duplicate chunks.

## Tech stack

- Python, FastAPI, Uvicorn
- ChromaDB (local vector store)
- gpt-oss-120b through the Groq API (OpenAI-compatible client)
- pypdf, LangChain text splitters

## Setup

Requires Python 3.11+ and a free Groq API key from console.groq.com.

```bash
git clone <https://github.com/gauravpandey8542/RAG-Q-A-Project.git>
cd <RAG-Q-A-Project>
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Mac/Linux
pip install -r requirements.txt
```

Copy `.env.example` to `.env` and add your key:

```
LLM_API_KEY=your_groq_key_here
```

Run the server:

```bash
uvicorn app.main:app --reload
```

Open http://127.0.0.1:8000/docs for the interactive API. The first upload is slow because the embedding model downloads once.

## API

| Endpoint | Description |
|---|---|
| `POST /documents` | Upload a PDF. Returns `doc_id`, page count, chunk count. |
| `GET /search?q=...` | Return the most similar chunks (retrieval only, no LLM). |
| `POST /ask` | Body: `{"question": "...", "doc_id": "..."}`. Returns an answer with sources. |

## Limitations and next steps

- Works with text-based PDFs only (scanned PDFs need OCR).
- No automated evaluation yet. Planned: a labeled question set to measure retrieval and answer quality.
- No front end yet. Planned: a simple Streamlit chat UI.
- Duplicate detection only catches byte-identical files.
